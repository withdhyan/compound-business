# Destination

**CB is the generic operating system for AI-native businesses — built founder-first
for one founder with many ideas.**

Bring an idea; the loop amplifies it (×100), decides, and builds it — and the
business state, rules, and receipts compound so the next idea starts smarter.
Generic by construction: no K coupling, no single-harness assumption, files not a
platform. Holon is the first proof. K is separate.

## What winning looks like

1. **You run every idea through it.** Nothing dies in a notes app; every idea
   becomes amplified variants, a decision, and built units — daily, not weekly.
2. **It outruns solo throughput.** One person with the loop ships what a team
   would; the compounding demo (week-0 vs week-N on the same kind of task)
   shows it.
3. **Holon reaches default-alive on it** — real money, the loop mostly running
   itself, the founder answering cards instead of pushing work.
4. **100 agent-native founders install it** — the people who already live in
   coding agents, who feel the pain of agents that forget and no gates on what
   they may do.
5. **The rulers hold.** Amplification quality is blind-scored against raw model
   output; the memory is checked for whether it changes decisions, not just
   whether it exists.

## The first-customer ruling

First customer = the founder. Build for this desk first, generic underneath.
Adoption is a consequence of the tool being real, not a design constraint on
day one. The audience never needs to know K exists.

# Path

## P0 — The creator loop (now)

`idea → amplify ×100 → decide → units → build → memory`

- **Idea intake**: one line in, recorded.
- **Amplify**: each idea developed into many concrete variants — angles,
  audiences, wedges, business models, first builds — ranked with reasons, not
  a listicle.
- **Decide**: the founder picks or reshapes; the decision is recorded (lever vs
  judgment) so the next amplification reads it.
- **Build**: chosen variants become units through the existing runtime
  (`planned → approved → running → review → shipped`), executed by whatever
  harness the founder runs.
- **Memory**: what worked, what died, and why lands as rules with receipts;
  the next idea's amplification reads them first.

## P1 — Dogfood (parallel with P0)

Run the loop on the founder's real ideas and on Holon's live moves (wedge,
capital, money). Every rough seam becomes a fix, one at a time, skill-TDD.

## P2 — Proof

The compounding demo and the amplification-quality benchmark, run on real
history. Publish claims only after the demo exists. Open-source release at
`withdhyan/compound-business` (runtime + roles + docs).

## P3 — 100 users

Adoption motion for agent-native founders: the repo as the install, the demo as
the pitch, no funnel. Land the first ten by hand; let them break it; fix seams.

## P4 — Money

Business model is an open decision. Candidates: hosted memory/sync, support,
enterprise governance. Not priced before the demo proves the loop.

# Critical assumptions (falsifiable)

1. **Amplification beats a raw model prompt.** Blind-score 20 amplified ideas
   vs 20 raw-model responses; if the panel can't tell, the loop's value is only
   in memory and gates.
2. **The build loop finishes.** Chosen variants actually reach shipped with
   review separation and receipts — not a pile of plans.
3. **Memory changes decisions.** Re-run idea classes with and without the
   learnings loaded; if outputs don't move, compounding is decorative.

# Constraints

- Generic: no K concepts in code or copy; any harness.
- Local-first files; no platform migration; the runtime writes only through the
  store.
- Gates hold: outbox for external, founder grants for reversible, founder
  receipts for irreversible, brake on.
- Claims never outrun artifacts.
